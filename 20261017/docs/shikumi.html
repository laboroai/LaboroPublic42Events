S3 仕組みの説明

今日作るエージェントの中で、何が起きているか

今日作るのは、質問を受けて、自分で書いたQAを探し、それをもとに答えるエージェントです。中では4つの仕組みが動いています。どれも、後半のS7とS8で起きることにつながります。

  1. LLM：次の言葉を確率で選ぶ
  2. RAG：資料を渡して答えさせる
  3. ベクトル検索：意味の近さで探す
  4. ツール呼び出し：説明を読んで、呼ぶかどうかを決める

1LLM：次の言葉を確率で選ぶ

LLMは、それまでの文章を読んで、次に来そうな言葉を候補ごとの確率で出します。その確率に従って1つ選び、また次の言葉を選ぶ。これをくり返して文章を作ります。

いちばん確率の高い言葉が毎回選ばれるとは限りません。そのため、同じ質問をしても、聞くたびに文面が変わります。

ためしてみる（数字は説明用のたとえです）

「42 Tokyoの魅力は、」の次に来る言葉の候補:

42 Tokyoの魅力は、…

S8で見ること　同じ質問をもう一度聞くと、前と同じ回答は返ってきません。言い回しが少し変わるだけでも、assert answer == "..." のようなテストは通りません。

2RAG：資料を渡して答えさせる

RAG（検索拡張生成）は、質問に関係しそうな資料を先に探し、その資料と質問をいっしょにLLMへ渡して答えさせる仕組みです。今日の資料は、皆さんが書くQAです。

LLMは、渡された資料だけで答えるとは限りません。もともと知っていることも混ぜて答えます。QAに書いていないことが、もっともらしく回答に入ることがあります。
S7で見ること　回答を公式サイトに載せてよいかを判定するとき、その一文がQAから来たのか、LLMが足したのかを見てください。判定が割れる理由の一つになります。

3ベクトル検索：意味の近さで探す

検索は、言葉が一致するかではなく、意味が近いかで探します。そのために、文章を数の並び（ベクトル）に変えます。今日使う埋め込みモデル（text-embedding-3-small）では、1つの文章が1536個の数になります。

意味の近い文章は、ベクトルの向きが近くなります。向きの近さを点数にしたのが、S5の検索コマンドに出る点数です。1に近いほど、意味が近いことを表します。

ためしてみる（2次元に縮めたたとえです。本物は1536次元）

質問を選ぶと、QAとの近さの点数が出ます。言葉が一致していなくても、意味が近ければ点数は高くなります。

順位点数QAの質問

S5で実際に出る画面

$ python search.py "今日のハンズオンの合言葉は？"
「今日のハンズオンの合言葉は？」に近いQA（点数は1に近いほど近い）
  1. 0.829  secret_qa.csv     今日のハンズオンの合言葉は？
  ...

点数は10/9に本物の埋め込みモデルで試したときの値です。このとき2位は0.115で、1位と大きく離れていました。皆さんのQAによって変わります。

S5で見ること　どのQAが何点で返るか、言い回しを変えても引けるかを試してください。

4ツール呼び出し：説明を読んで、呼ぶかどうかを決める

エージェントには、Pythonの関数を「ツール」として渡せます。LLMは関数の中身のコードを読みません。読むのは、関数の名前、引数とその型、docstring（説明文）だけです。それを読んで、この質問に答えるのにツールを呼ぶべきかを、LLMが自分で決めます。

たとえば、こんな関数を渡すと

def get_menu(day: str) -> dict:
    """指定した曜日の学食のメニューを返す。学食や昼ごはんについて聞かれたときに使う。

    Args:
        day: 曜日。「月」「火」のように1文字で渡す。
    """
    ...

LLMに見えているのは、これだけです

名前:   get_menu
説明:   指定した曜日の学食のメニューを返す。学食や昼ごはんについて聞かれたときに使う。
引数:   day（文字列）  曜日。「月」「火」のように1文字で渡す。
説明文の書き方しだいで、ツールは呼ばれたり呼ばれなかったりします。「何をするツールか」と「いつ使うか」を書いておくと、LLMが判断しやすくなります。
